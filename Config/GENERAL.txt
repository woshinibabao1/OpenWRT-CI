# ===== 常见第三方插件依赖（2026-09-22 补全）=====
# 起因：装第三方插件时卡在「依赖缺失 kmod-inet-diag」。核实 V0.18 基线固件的
#   apk 数据库证实：mihomo-alpha 的依赖里就写着 `ca-bundle ip-full kmod-inet-diag
#   kmod-tun libc`，nikki 的更长（也含 kmod-inet-diag）。即上游插件**明确声明了它**，
#   而本固件一直没有。
#
# ★ 为什么这类包必须随镜像编入，而不能等缺了再 apk add：
#   kmod-* 的依赖串里带**内核指纹**（形如 `kernel=6.18.52~<build-hash>`）。
#   本固件是自编译内核（`cat /proc/version` 里带我们自己 runner 的 build 号），
#   在线仓库里的同名 kmod 是给官方内核编的 —— 装上去要么被 apk 直接拒绝，
#   要么装上因 vermagic 不一致而 modprobe 失败（症状：包在、功能没有）。
#   用户态包没有这个问题（可以直接在线装），所以**只有 kmod 必须预置进镜像**。
#
# 选包依据（不是"能想到的都加上"）：
#   ① 与**两套基线固件**做差集后取**交集**：V0.18（apk 时代）与
#      Mwrt-H5000M-1139-24（opkg 时代）共有 284 个包，其中我方没有的逐个过了一遍 —
#      两套不同来源的固件都装，说明不是哪一家的偏好。kmod 部分另与真机逐项核对。
#      （真机当前 167 个 kmod；两基线都有的那批见下。）
#   ② 每个符号都在上游源码里逐个核过（immortalwrt master 的
#      package/kernel/linux/modules/*.mk，共 1188 个 KernelPackage 定义）——
#      ★ 因为 kconfig 对**不存在或依赖不满足**的符号是**静默丢弃**：写错名字不报错、
#      只是"配了等于没配"。CI 里另加了一条断言复核本段（见 WRT-CORE.yml「常见依赖断言」）；
#   ③ 真机核过这些能力**确实没有**（不是已内建）：/sys/module/inet_diag、
#      /sys/module/br_netfilter、/sys/module/nft_compat 三个都不存在，
#      /lib/modules/6.18.52 里也没有对应 .ko —— 所以不是白加；
#   ⑤ 明确**不加**的 —— 分两类：
#      (a) 别的设备/别的场景：kmod-crypto-eip（MTK 老平台加密引擎；本机用 EIP197/safexcel）、
#          kmod-mt7987-2p5g-phy（本机已由 kmod-phy-mediatek-2p5g 覆盖，只是包名不同）、
#          kmod-qmi_wwan_f/q/s、kmod-usb-serial-qualcomm、kmod-usb-net-huawei-cdc-ncm
#          （都是别的模组的驱动；本机 MT5700 走 CDC-NCM/option，通用 QMI 也已编入）、
#          kmod-nf-ipvs（只服务容器编排，本机没有 docker/kube-proxy）、
#          kmod-nf-conntrack6（新版已并入 kmod-nf-conntrack，上游没有这个独立包名）。
#      (b) 两基线里属于"产品级选择"或"传递依赖"的，不因基线有就照抄：
#          docker/containerd/runc/tini/dockerd、taskd/luci-app-store/luci-lib-taskd/
